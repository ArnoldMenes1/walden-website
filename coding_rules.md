# Coding Rules

## Langage

Toujours utiliser TypeScript.

Ne jamais utiliser JavaScript sauf nécessité.

---

## Architecture

Respecter SOLID.

Respecter Clean Architecture.

Favoriser la composition plutôt que l'héritage.

---

## Qualité

Code lisible.

Fonctions courtes.

Noms explicites.

Pas de duplication.

Toujours documenter.

---

## Organisation

Chaque fonctionnalité doit être isolée.

Chaque dossier possède une responsabilité unique.

---

## Tests

Toute nouvelle fonctionnalité possède des tests.

Ne jamais casser les tests existants.

---

## Git

Commits atomiques.

Messages conventionnels.

feat:

fix:

docs:

refactor:

test:

style:

perf:

ci:

---

## Documentation

Toute API est documentée.

Toute fonction complexe est expliquée.

---

## UI

Responsive.

Accessible.

Dark mode compatible.

Animations fluides.

---

## Performance

Lazy Loading.

Code Splitting.

Optimisation des images.

Caching.

---

## Sécurité

Validation des entrées.

Jamais de secret dans le code.

Variables d'environnement uniquement.

Protection XSS.

Protection CSRF.

Protection SQL Injection.

---

## Avant chaque modification

Analyser le problème.

Expliquer la stratégie.

Lister les fichiers.

Coder.

Tester.

Résumer les changements.
